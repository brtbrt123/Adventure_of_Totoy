# Architecture: core / presentation interface

Status: **draft 2**, implemented by the combat vertical slice in `core/` (one room, player with sword vs the Mossbound Colossus) and covered by headless tests. It will keep changing as the slice is playtested. Changes go through Claude Code (owner of `core/` and this file); Codex builds against it and reports gaps in task notes.

## Principles

1. `core/` has no rendering, UI or audio code and runs headless. `presentation/` has no game rules.
2. **The core decides, presentation draws.** Hits, damage, parry timing, posture and cooldowns are core results. Presentation never recomputes them.
3. **Fair tells (from the game design):** every attack's warning is produced by the core as the *same geometry* that later applies damage (`telegraph.gd`). Presentation draws that geometry; it never invents its own. A test checks warning area == hit area on a grid of positions, and another checks that aim never changes after an attack commits.
4. Presentation sends *intents*, not key presses. Mapping keyboard/controller to intents lives in `presentation/`.
5. Communication is one way per channel: input intents in; snapshot and events out. No layer calls into the other's internals.

## How to use the core

```gdscript
const GameCore := preload("res://core/game_core.gd")
const InputFrame := preload("res://core/input_frame.gd")

var core: GameCore = GameCore.new(seed_value)   # deterministic: same seed + same inputs = same fight

func _physics_process(_delta: float) -> void:   # project physics ticks must be 60 per second
	var frame: InputFrame = InputFrame.new()
	frame.move = Input.get_vector("left", "right", "up", "down")
	frame.parry_pressed = Input.is_action_just_pressed("parry")
	core.step(frame)                             # advance exactly one tick
	var snap := core.snapshot()                  # read-only view for drawing
	for event in core.last_events:               # facts from this tick, in order (also via core.event_emitted)
		pass
```

Core scripts are referenced with `preload` constants, not `class_name`, so they load in headless runs without the editor's class cache.

## Time

Fixed tick of **60 Hz** (`Tuning.TICK_DT`). One `step()` is one tick. All times in the interface are ticks (`int`) so results are deterministic and testable; presentation converts to seconds for effects. Randomness uses a seeded `RandomNumberGenerator` owned by the core. After `result` leaves `playing`, `step()` does nothing.

## Channel 1: input intents (presentation to core): `core/input_frame.gd`

One `InputFrame` per tick:

| Field | Type | Meaning |
|---|---|---|
| `move` | `Vector2` | desired move direction, length 0..1 |
| `aim` | `Vector2` | aim direction (bow/staff later), zero if none; otherwise facing follows `move` |
| `attack_pressed` / `attack_held` | `bool` | normal attack (sword) / draw / cast |
| `parry_pressed` | `bool` | gold parry |
| `dash_pressed` | `bool` | dash |
| `weapon_active_pressed` | `bool` | the equipped weapon's active this tick (right click; Black Katana buff, Dual Dagger Lightning Form or Chain Scythe Reaper's Coil, which is aimed by `aim`; see "Weapon active", "Dual Dagger", "Chain Scythe") |
| `weapon_equip` | `StringName` | equip exactly this weapon this tick (`black_katana`, `dual_dagger`, `chain_scythe`), empty = none; sent by the character menu's inventory (see "Weapon equip"). Replaced the Q cycle `weapon_swap_pressed` on 2026-10-21 |
| `skill_pressed` | `int` | skill slot 1, 2 or 3 pressed this tick, else 0: triggers the aspect **equipped in that slot** (default Z = 1 Breaking Edge, X = 2 Gale Cut, C = 3 Moon Cleave; see "Aspects, Spirit Lantern, Phantom Cut"; the key mapping is presentation's job) |
| `aspect_equip` / `aspect_equip_slot` | `StringName` / `int` | equip aspect `aspect_equip` (an `Aspects.ALL` id) into slot `aspect_equip_slot` (1-3) this tick; empty = none. Sent by the character menu (see "Aspects") |
| `interact_pressed` | `bool` | talk, open (exploration only, `core/explore_core.gd`; the fight ignores it); while a dialogue runs it shows the next line |
| `skip_pressed` | `bool` | ends a running dialogue (exploration only; ignored when nobody talks) |

## Channel 2: read-only snapshot (core to presentation): `core/snapshots.gd`

`core.snapshot()` builds a new `Snapshots.GameSnapshot` each call; do not mutate it or keep references to core objects.

- `tick`, `result` (`playing`, `victory`, `defeat`)
- `player: EntitySnapshot`, `entities: Array[EntitySnapshot]` (the boss; more later)
- `telegraphs: Array[TelegraphSnapshot]`
- `skill_attacks: Array[SkillAttackSnapshot]` (live skill attacks, see "Sword skills")
- `lanterns: Array[LanternSnapshot]` (Spirit Lanterns in the world, see "Aspects")
- `echoes: Array[EchoSnapshot]` (Echo Step anchors, see "Echo Step, Stone Ward, Sprint")
- `obstacles: Array[ObstacleSnapshot]` (the solid props of the arena, the same list every tick)
- `hud: HudSnapshot`

### The arena: size, solid props, camera

- **Size.** `Tuning.ARENA_SIZE` is **800x480** (50x30 tiles). Bodies stay `Tuning.ARENA_MARGIN` (28 px) inside the edge. Spawns: `Tuning.PLAYER_START` (312, 250), `Tuning.BOSS_START` (488, 250); no prop overlaps them.
- **Solid props (core).** `core/arena_layout.gd` builds a fixed list of `core/obstacle.gd` circles, colliders only (every `visual_id` is empty since 2026-10-21: the ground painting draws the structures). Two kinds: the forest edge (`BOUNDARY`, the clearing's outline: the plaza inside its ruined walls, the west wall gap and the east gap with the dirt path; a chain of `BOUNDARY_RADIUS` 36 circles every <= 24 px just outside every edge, so the forest and the outline walls cannot be entered; `ARENA_MARGIN` stays as the outer clamp) and `SOLIDS` + `ALTAR`, placed on the painted statue shrine, chests, pillars, fallen columns, rubble piles, broken south walls and the altar. `game_core.gd` resolves the player and the boss against them in small steps (no tunnelling, also for dashes, Gale Cut and the boss charge). Nothing solid stands in the rune ring or on the raised platform (the boss fits everywhere in x 220..580, y 130..350). Check placement on `docs/previews/arena_colliders_overlay.png` (`tests/capture_arena_colliders.gd`, headless).
- **`ObstacleSnapshot`:** `id`, `visual_id` (sprite name, empty for an extra collider), `feet` (where presentation places the sprite by its anchor), `visual_scale`, `center` and `radius` (the collision circle). Presentation draws the props only from this list; it must not add solid-looking things the core does not know about.
- **Ground and decoration (presentation).** The floor is `presentation/arena/arena_ground.png`: the owner's target painting `art/reference/arena_target_look.png` resized to 800x480 and snapped to the palette (no reserved colours) by `tools/art/make_arena_ground_from_reference.py`. Walls, pillars, statue, chests, altar, rubble and the forest are painted in (no tall prop is a separate sprite). Since 2026-10-22 the tall ones (statue, pillars, the SE slab, the altar, the broken south walls, the rubble piles) are also **depth occluders** (`presentation/common/depth_occluders.gd`, see "Scenes and exploration mode"): `arena.gd _draw()` puts them into its y-sorted list (`OCCLUDER_SCENE` `arena`) and draws them at the ground's modulate (`GROUND_MODULATE` 0.92), so the hero or the boss standing north of a pillar's base is drawn behind it. The actors' ground shadow is the shared `presentation/common/actor_shadow.gd` (hero radius 10, boss 20). `presentation/arena/arena_decor.gd` is kept for non-solid extras, but its list is empty. Review captures: `tests/capture_arena_review.gd` (windowed) writes `docs/previews/arena_full_v2.png` and `arena_view_*.png`; `tools/art/compare_arena_target.py` writes `arena_vs_target.png`.
- **Camera (presentation).** The screen stays 320x180. `arena.gd` owns a `Camera2D` that follows the player (leaning 22% towards the boss), snapped to whole pixels and clamped so the view never leaves the arena. `view_origin` is the world position of the screen's top-left corner; the HUD is in screen space, so world positions given to it (the boss head for the boss panel) are converted with `world - view_origin`.

`EntitySnapshot`: `id`, `visual_id` (`&"totoy"`, `&"mossbound_colossus"`), `state`, `state_ticks`, `position` (pixels), `facing`, `hp`, `max_hp`, `posture`, `posture_max`, `invulnerable`, `combo_index` (player only, see the sword combo below; `0` for the boss), `skill_id` (player only: `breaking_edge`, `gale_cut` or `moon_cleave` during the `skill_*` states, otherwise empty), and for the player the weapon fields `weapon_id`, `weapon_buff_active`, `weapon_buff_ticks_left`, `attack_speed_mult` (see "Weapon active") and `combo_max`, `weapon_form`, `move_speed_mult`, `lightning_blink_index`, `lightning_blink_tick`, `lightning_blink_from`, `lightning_blink_to` (see "Dual Dagger"), `reaper_coil_phase`, `reaper_coil_phase_tick`, `reaper_coil_from`, `reaper_coil_target`, `reaper_coil_spin_hit`, `equipped_aspects`, `phantom_ticks_left`, `phantom_pending_echoes` (see "Aspects"), `sprint_ticks_left`, `echo_invuln_ticks`, `ward_ticks_left`, `ward_stored` (see "Echo Step, Stone Ward, Sprint"); for the boss `dragged` and `stagger_ticks_left` (see "Chain Scythe").

States: player `idle walk dash parry parry_recovery attack_windup attack_active attack_recovery skill_windup skill_active skill_recovery lightning_barrage reaper_coil ward dead` (`ward` = Stone Ward, see "Echo Step, Stone Ward, Sprint"); boss `idle attack recover posture_broken staggered dead`.

### Sword combo (player)

The sword is a three-swing combo: `combo_index` 1, 2, 3 = art `hero2_attack1`, `attack2`, `attack3`. The core owns all of it (progression, timing, hit resolution); presentation only reads `player.combo_index` together with `state` and `state_ticks`.
- **Meaning of `combo_index`:** during `attack_windup`, `attack_active` and `attack_recovery` it is the swing in progress (1-3). While idle it is `1`, except for a short chain-grace window (`COMBO_GRACE_TICKS`) right after swing 1 or 2 ended, when it still shows that swing. Pick the attack animation from `combo_index` whenever `state` starts with `attack_`.
- **Frames per swing (the art has six):** windup = frames 1-2, active = 3-4, recovery = 5-6. Each swing has its own tick counts (`SWING_WINDUP_TICKS`, `SWING_ACTIVE_TICKS`, `SWING_RECOVERY_TICKS` in `core/tuning.gd`, one entry per swing), so spread the frames over `state_ticks` of the current state, not over fixed tick counts.
- **Chaining:** an attack press during the last `COMBO_BUFFER_TICKS` of a swing's recovery is remembered; the next swing starts the tick recovery ends (the state goes `attack_recovery` -> `attack_windup` with no idle tick, `combo_index` + 1). Earlier presses are ignored. If nothing was buffered, a press within `COMBO_GRACE_TICKS` after the swing still continues the chain. After swing 3 the combo is over: the next press starts swing 1 (a buffered press at the end of swing 3 starts a new combo at 1).
- **Resets to 1:** the player takes damage, dashes, parries (the press, or a successful parry), dies, stops chaining (grace ran out) or finishes swing 3. A queued press is dropped with the reset.
- **Hits:** each swing hits at most once (the first active tick that has the boss in range and arc). Damage and reach scale per swing (`SWING_DAMAGE_MULT`, `SWING_RANGE_MULT`). The `attack_hit` event carries `combo_index`.

### Sword skills (player, test set)

Three skills for testing the Aspect system, selected by `skill_pressed` 1-3 (Z, X, C). Usable from `idle`, `walk` and the recovery of a normal swing (a skill cancels that recovery and resets the combo); not during a parry, dash, another skill or after death. Each runs `skill_windup` -> `skill_active` -> `skill_recovery` (read `snapshot.player.skill_id` for which). None grants invulnerability. Phase lengths and every number are in `core/tuning.gd` (`BREAKING_EDGE_*`, `GALE_CUT_*`, `MOON_CLEAVE_*`); spread frames over `state_ticks` of the current state.
- **Direction:** fixed when the skill is pressed: the **move input** if the player is moving, else `aim`, else the facing. The player's `facing` is set to it. (The mouse aim no longer beats the way the player is walking.)
- **Edge:** the cost is spent on the press and is not refunded if the skill is interrupted. Each skill has its own cooldown (`hud.skill_cooldown_ticks`).
- **Attack objects:** the tick a skill enters `skill_active`, the core creates one **skill attack** with an id and emits `skill_released`. It is listed in `snapshot.skill_attacks` while it lives. A cast hits each target at most once; the confirmed hit is an `attack_hit` event with `skill_id` and `attack_id`. Damage uses the normal-hit rules (armored factor; counter multiplier during a posture break; posture added only when not broken).
- **`SkillAttackSnapshot`:** `id`, `owner_id`, `skill_id`, `shape` (`arc`, `lane`, `projectile`), `position` (arc/lane: the player; projectile: its centre now), `direction`, `start` and `end` (lane/projectile endpoints; `end` is where it ends if nothing shortens it), `width`, `size` (arc reach), `half_angle` (arc, radians), `start_tick`, `end_tick`, `ticks_left`, `hit_target_ids`.
- **Breaking Edge (1), parry retaliation:** only while `hud.retaliate_ticks_left > 0` (set by a successful parry, cleared by damage or use) and with `BREAKING_EDGE_EDGE_COST` Edge. A 3-tick windup that is also the forward step (`BREAKING_EDGE_STEP`), then a short melee `arc` (one confirmed hit) with strong posture damage (two break the boss).
- **Gale Cut (2), dash corridor:** 35 Edge, 300-tick cooldown. A short windup (no movement), then during `skill_active` the player dashes `GALE_CUT_SPEED` px per tick for `GALE_CUT_ACTIVE_TICKS` ticks (about 120 px). During `skill_active` the player **passes through the boss** (no collision with enemies) but is still stopped by the arena walls. The `lane` attack damages whatever the **actually travelled** segment (previous position to the final position each tick, after the wall clamp) touches, widened by `GALE_CUT_LANE_WIDTH` (18 px) plus the target's radius, once per target. Normal enemy collision is back from the first `skill_recovery` tick (or the moment the dash is interrupted): if the player ends inside the boss they are moved to the nearest free spot (first on the side they were heading, then around the boss if a wall blocks it), so they never finish stuck in an enemy. The windup is still solid. The lane lives until the dash ends or is interrupted (damage ends it at once). The lingering blade trail is cosmetic: presentation draws it from the positions, it deals no damage.
- **Moon Cleave (3), sword-aura projectile:** `MOON_CLEAVE_EDGE_COST` Edge, a committed hold (`MOON_CLEAVE_WINDUP_TICKS`, slow movement). Damage only comes from the projectile. If the hold is interrupted nothing spawns (and the Edge is gone). On the first `skill_active` tick the `projectile` spawns `MOON_CLEAVE_SPAWN_OFFSET` px ahead, then travels `MOON_CLEAVE_TRAVEL` px at `MOON_CLEAVE_SPEED` px per tick, `MOON_CLEAVE_WIDTH` px wide, piercing (each target once). It then lives on its own: taking damage or dying after the release does not remove it. The recovery cannot be cancelled by dash, parry or attack.
- **Collision:** swept: each tick tests the whole segment moved (so a fast mover cannot tunnel) against the target circle widened by half the lane/projectile width.
- **Presentation to do (Codex):** a Gale Cut dash now moves the player during `skill_active` (before it moved during the windup), so the dash trail and effect timing must follow `skill_active` and `snapshot.skill_attacks`; draw the Moon Cleave projectile from `skill_attacks` (`position`, `direction`, `width`, `ticks_left`) and keep it after the player's state changes; use `skill_released` for release sounds and effects. `tests/smoke_skills_presentation.gd` sets no Edge before pressing X, which now costs 35.

### Weapon active: Black Katana buff (player)

The equipped weapon is `snapshot.player.weapon_id` (`black_katana` or `dual_dagger`; see "Dual Dagger" for the second weapon, the swap and Lightning Form, which reuse this plumbing). Its active is **right click**: input field `InputFrame.weapon_active_pressed` (true for the tick of the press; mapping the mouse button is presentation's job). The core owns everything else.

**Numbers** (`core/tuning.gd`, `BLACK_KATANA_*`, set by the human on 2026-10-19, not yet playtested): duration 600 ticks (10 s), cooldown 1800 ticks (30 s, counted from the activation), Edge cost 50, attack speed x1.5, damage x1.4. Nothing else in core hard-codes them; presentation must read them from `Tuning` or the snapshot. Open design questions: can it be re-pressed to refresh (not now), does the buff change skill speed (it does not now), should damage taken or a parry affect it (they do not now).

**Rules (as built):**
- Needs: weapon `black_katana`, not dead, enough Edge, cooldown ready, and **no buff running** (it cannot be refreshed). A refused press does nothing and emits no event.
- It is a **free action**: no state change, no animation lock, allowed in any state except `dead` (idle, walk, attack, dash, parry, skill). The cost is spent on the press.
- It **stays active through movement, attacks, dashes, parries, skills and damage**. It ends only when the duration runs out or the player dies. A new fight (`GameCore.new()`) starts without it.
- **Attack speed** applies to the normal sword swings: every phase length (windup, active, recovery) is `Player.scaled_ticks(base, mult)` = `round(base / mult)`, at least 1 tick. Skill timings are unchanged.
- **Damage** is multiplied on normal swings and skill hits (counter hits too). Both multipliers are **locked** when a swing starts and when a skill is released: a swing never changes speed halfway, and a projectile released under the buff keeps its damage even if the buff ends before it lands.
- The combo buffer, grace and resets are unchanged (the buffer window never extends past the shorter recovery).

**Snapshot:**
- `player.weapon_id`, `player.weapon_buff_active`, `player.weapon_buff_ticks_left` (0 when inactive), `player.attack_speed_mult` (the locked speed of the swing in progress during `attack_*` states; otherwise the current buff speed, 1.0 without the buff).
- `hud.weapon_buff_duration` (0 for a weapon without an active), `hud.weapon_buff_cooldown_ticks` / `hud.weapon_buff_cooldown_max`, `hud.weapon_buff_edge_cost`. (The boss entity has `weapon_id` empty.)

**Events:**
- `weapon_buff_started`: `entity_id`, `weapon_id`, `duration` (ticks), `attack_speed_mult`, `damage_mult`.
- `weapon_buff_ended`: `entity_id`, `weapon_id`, `reason` (`expired` or `death`).
The buff is active from the activation tick through the `duration`-th tick; `weapon_buff_ended` fires on the tick after the last active one.

### Dual Dagger: second weapon, swap, lightning finisher, Lightning Form (player)

Added 2026-10-19 (core only; numbers are first guesses, nobody has played it). Every number is in `core/tuning.gd` (`WEAPON_SWAP_*`, `DAGGER_*`, `LIGHTNING_*`). `core/weapons.gd` (`const Weapons := preload("res://core/weapons.gd")`) is the one place that picks a weapon's numbers by `weapon_id`; presentation should use it too instead of branching on the weapon: `Weapons.combo_max(w)`, `Weapons.swing_phases(w, combo_index)` -> `[windup, active, recovery]` base ticks, `Weapons.windup_ticks/active_ticks/recovery_ticks(w)`, `Weapons.active_duration/active_cooldown/active_edge_cost(w)`, `Weapons.active_form(w)`, `Weapons.blink_direction(index)`.

**Swap (Q, until 2026-10-21; now `weapon_equip`, see "Weapon equip").** The Q press toggled `black_katana` <-> `dual_dagger`. Allowed only in `idle` or `walk` (not during a swing, its recovery, a skill, dash, parry or after death), never while a weapon buff/form runs, and not within `WEAPON_SWAP_LOCKOUT_TICKS` (20) of the previous swap. It is a free action (no state change; an attack pressed the same tick already uses the new weapon). It resets the combo to 1. A refused press does nothing and emits nothing. The player always starts a fight with the Black Katana. Each weapon keeps **its own active cooldown**, and all of them keep counting down while put away, so swapping never resets or skips one.

**Dagger combo.** 4 swings (`combo_index` 1-4 while the dagger is equipped; `snapshot.player.combo_max` says 3 or 4). Same buffer/grace/reset rules as the katana combo; after swing 4 the combo is over. Per-swing tables `DAGGER_SWING_WINDUP_TICKS` [4,4,4,6], `DAGGER_SWING_ACTIVE_TICKS` [2,2,2,3], `DAGGER_SWING_RECOVERY_TICKS` [6,6,6,12] (12/12/12/21 ticks against the katana's 19/18/29), reach x0.75 of `ATTACK_RANGE`, damage `ATTACK_DAMAGE` x [0.6,0.6,0.6,0.9], Edge +`DAGGER_EDGE_PER_HIT` (20) per hit. Alternating hands is presentation only (odd/even `combo_index`). Skills Z/X/C work the same with both weapons. **Presentation reads the swing lengths through `Weapons.swing_phases(weapon_id, combo_index)`** (scaled with `Player.scaled_ticks(base, attack_speed_mult)`; done in `presentation/arena/animation.gd`).

**Lightning strike (dagger finisher).** When the 4th dagger swing **connects** (the same `attack_hit` as always, with `combo_index` 4 and now also `weapon_id`), a bolt from the sky also hits that boss on the same tick, right after the `attack_hit`. No telegraph, it always lands on the hit boss; a whiffed swing 4 calls nothing, and it happens at most once per swing. Damage `LIGHTNING_STRIKE_DAMAGE` (20) under the normal-hit rules (x`ARMOR_DAMAGE_FACTOR` = 5 on the armored boss; x`COUNTER_DAMAGE_MULT` = 80 if the swing was a counter), plus `LIGHTNING_STRIKE_POSTURE` (8) when not a counter; no Edge gain. Event `lightning_strike`; the boss also emits its usual `damage_taken`. **Presentation draws the bolt from the sky down onto `position`** on that event (the boss position at the strike), with flash/shake/sound. There is no separate `attack_hit` for the bolt; show its damage from the event.

**Lightning Form (dagger right click) = the Lightning Barrage only.** Changed 2026-10-19 on the human's instruction: the 6 s form with x2 attack speed, x1.25 walking speed and blinking manual swings is **removed**. The right click uses the same plumbing as the katana buff (`weapon_active_pressed`, Edge spent on the press, no use while it runs, cooldown counted from the activation, `weapon_buff_started` / `weapon_buff_ended`), but the "form" lasts exactly as long as the barrage below: `Weapons.active_duration(dual_dagger)` = `Weapons.barrage_total_ticks()` (55), `weapon_form` is `lightning_form` and `weapon_buff_active` is true only while the barrage runs, and `weapon_buff_ended` (`expired`, or `death`) fires on the barrage's last tick, right after `lightning_barrage_ended`. The buff timer never ends it by itself. Numbers: cost `LIGHTNING_FORM_EDGE_COST` 60, cooldown `LIGHTNING_FORM_COOLDOWN_TICKS` 1500 (25 s from the activation); no attack speed, damage or walking bonus (`weapon_buff_started` reports 1.0 for all three). It needs a living boss: with the boss dead the press is refused (no Edge, no cooldown, no event). Swap is refused during the barrage and allowed on the next tick after it. After the barrage the dagger is plain again: swings do not blink, no aura, no lightning afterimages.

**Lightning Barrage (added 2026-10-19, the human's request "slash on every direction, at least 8 slashes").** Activating Lightning Form (the boss must be alive; it works at **any distance**) starts the automatic barrage on the activation tick (after `weapon_buff_started`, event `lightning_barrage_started`). The player enters state `lightning_barrage`: no movement, no actions (attack, dash, parry, skills, swap, active are ignored), facing locked on the boss, and **invulnerable** the whole time (`snapshot.player.invulnerable`; boss attacks that touch the player do nothing). The core then plays a fixed timeline counted from the activation (`state_ticks`): slash k = 1..8 blinks on activation + `LIGHTNING_BARRAGE_START_DELAY_TICKS` (1) + (k-1) x `LIGHTNING_BARRAGE_INTERVAL_TICKS` (6), from side `LIGHTNING_BLINK_ORDER[k-1]` (so the 8 slashes come from the 8 directions, each once). Placement: the spot is `boss.position + Weapons.blink_direction(d) * LIGHTNING_BLINK_DISTANCE` (30 px from the boss centre; `d` 0-7 is `Vector2.RIGHT` rotated by d x 45 degrees, y down), kept inside the arena, pushed out of props, outside the boss and within the dagger reach; each blink also gives `LIGHTNING_BLINK_INVULN_TICKS` (6) i-frames; a blocked side falls back to the nearest free side **not yet used by this barrage** (tries d, d+1, d-1, d+2, ...), else the nearest free side; no free spot at all: the slash stays where the player is. Each slash emits `lightning_blink` (with `barrage_slash` k) and lands `LIGHTNING_BARRAGE_HIT_DELAY_TICKS` (2) later as one `attack_hit` (`barrage_slash`, `weapon_id`, no `combo_index`) if the boss is within the dagger reach: damage `ATTACK_DAMAGE` x `LIGHTNING_BARRAGE_DAMAGE_MULT` (0.6), normal-hit rules (armored x0.25, `NORMAL_HIT_POSTURE`, +`LIGHTNING_BARRAGE_EDGE_PER_HIT` (5) Edge; a counter while the posture is broken, x4 plus the Edge bonus, spends all Edge; a slash that breaks the posture makes the next ones counters). The 8th slash also calls the **lightning strike** (same rules as the swing-4 bolt; event `lightning_strike` with `source` `barrage`, `barrage_slash` 8, `combo_index` 0; the swing finisher's event now has `source` `swing`). **Reaper's Coil (scythe right click).** Same plumbing as Lightning Form: `weapon_active_pressed` with the scythe equipped is a free action (any state but `dead`, it takes over whatever the player was doing, exactly like the barrage); it needs a living boss (with the boss dead the press is refused: no Edge, no cooldown, no event), costs `REAPER_COIL_EDGE_COST` 50 Edge on the press, its cooldown `REAPER_COIL_COOLDOWN_TICKS` 1200 (20 s) counts from the activation, and it cannot be used again while it runs. `weapon_buff_started` (`form` `reaper_coil`, `duration` = `Weapons.reaper_coil_total_ticks()` = 58, all multipliers 1.0) fires first; `weapon_form` is `reaper_coil` and `weapon_buff_active` true exactly while the skill runs; `weapon_buff_ended` (`expired`, or `death`) fires right after `reaper_coil_ended`. No lingering buff. Direction: `InputFrame.aim` of the press tick (the mouse), else the facing; fixed for the whole skill.

The player is in state `reaper_coil` for the whole skill: **invulnerable**, no movement, no actions (attack, dash, parry, skills, swap and active presses are ignored). The core runs the phases (`snapshot.player.reaper_coil_phase`, `reaper_coil_phase_tick` = ticks since the phase began, 0 on its first tick):
1. **`hook`** (activation tick A = phase tick 0): from A+1 the chain tip is `phase_tick x REAPER_COIL_HOOK_SPEED` (12.5) px out along the direction, up to `REAPER_COIL_HOOK_RANGE` 150 px (12 ticks). Each tick the first thing along the whole chain decides: the boss circle widened by half `REAPER_COIL_CHAIN_WIDTH` (8) -> **hooked** (`reaper_coil_hooked`, phase `drag` from this tick); a solid prop (widened the same way) or the arena wall -> **missed** at that point (`reaper_coil_missed`, `blocked_by` `prop`/`wall`); full range without contact -> missed (`range`). A prop between the player and the boss always stops the chain. `reaper_coil_target` is the tip.
2. **Hooked: `drag`.** On the hook tick the boss's running attack is **cancelled** (`Boss.interrupt_for_drag()`: its telegraphs are dropped, so nothing of it can hit; a charge stops) and it becomes `staggered` with `dragged` true (a boss whose posture is already broken stays `posture_broken`; its counter window pauses while dragged and then goes on). From the next tick the core pulls the boss `REAPER_COIL_DRAG_SPEED` 10 px per tick straight toward the player through the same prop sweep as all movement (`move_resolved`, then kept in the arena and out of props) until its centre is `BOSS_RADIUS + PLAYER_RADIUS + REAPER_COIL_DRAG_GAP` = 34 px from the player (edges 8 px apart). The drag ends on the tick the boss arrives, a tick gains less than `REAPER_COIL_DRAG_BLOCKED_PX` (props block it: it stays where it got), or after `REAPER_COIL_DRAG_MAX_TICKS` 16: `reaper_coil_drag` fires, `dragged` turns false and the **stun** starts: the boss stays `staggered` (no attacks, no walking, no new telegraphs) for exactly `REAPER_COIL_STAGGER_TICKS` 45 ticks counted from that tick (`stagger_ticks_left` 44 .. 0 in the snapshot), then `recover` for `BOSS_STAGGER_RECOVER_TICKS` 12 and its normal cooldown. Hitting a staggered boss uses the normal rules (armored, posture); a posture break during the stun replaces it with the normal counter window. `reaper_coil_target` is the boss edge the chain holds.
3. **`spin`** (automatic, starts the tick the drag ends, `REAPER_COIL_SPIN_TICKS` 20): a full circle around the player. Spin hit k (1-2) lands on spin tick `REAPER_COIL_SPIN_FIRST_HIT_TICK + (k-1) x REAPER_COIL_SPIN_HIT_INTERVAL_TICKS` (4 and 12): `reaper_coil_spin` (`hit_index`, `position`, `radius` 36, `connects`), and when the boss edge is within `REAPER_COIL_SPIN_RADIUS` 36 px a real hit through the normal rules: `ATTACK_DAMAGE x REAPER_COIL_SPIN_DAMAGE_MULT` (1.2; armored 3, counter 48 plus the Edge bonus), `REAPER_COIL_SPIN_POSTURE` 10, `REAPER_COIL_EDGE_PER_HIT` 5 Edge; `attack_hit` with `reaper_coil_hit` k and `weapon_id`. `reaper_coil_spin_hit` counts the hits done. The spin does not end the stun early.
4. **`recovery`** `REAPER_COIL_RECOVERY_TICKS` 10, then `reaper_coil_ended` (`complete`) and the player is `idle`.
- **Missed: `pull`.** From the tick after the miss the player is pulled `REAPER_COIL_PULL_SPEED` 8 px per tick toward the anchor (`reaper_coil_target`) through the prop sweep, never into the boss; it ends on arrival, when blocked or after `Weapons.reaper_coil_pull_max_ticks()` (20); then `recovery` `REAPER_COIL_PULL_RECOVERY_TICKS` 8 and `reaper_coil_ended` (`missed`). No stun, no spin. A boss farther than 150 px is simply a miss (the coil is still allowed).
- **Early ends:** the boss dies (`boss_dead`, before `game_result`); the player dies (`death`, emitted by `Player.die` before `weapon_buff_ended`/`entity_died`; a boss held mid-drag is released into its normal stun on the next step).

**Timing (hit, boss straight ahead at distance d, open field):** hook tick H = A + ceil((d - 24) / 12.5); drag end D = H + ceil((d - 34) / 10) (at least 1); spin hits at D+4 and D+12; spin ends D+20; `reaper_coil_ended` at D+30; stun until D+44, boss `recover` from D+45. Example d = 100: H = A+7, D = A+14, end A+44. **Miss at full range:** missed at A+12, pull 19 ticks, ended at A+39.

**Snapshot:** player `reaper_coil_phase` (`hook`, `drag`, `spin`, `pull`, `recovery`; empty when not running), `reaper_coil_phase_tick`, `reaper_coil_from` (the player while it runs), `reaper_coil_target` (hook: the tip; drag: the boss edge held; pull: the anchor; spin/recovery: unchanged from the end of the drag, the chain is put away), `reaper_coil_spin_hit` (0-2); boss `dragged`, `stagger_ticks_left`, state `staggered`. **Equipping.** `Player.equipped_aspects` (3 different known ids; a new fight starts with `breaking_edge, gale_cut, moon_cleave`, so nothing changes unless the menu re-slots). `skill_pressed N` triggers `equipped_aspects[N-1]`. `InputFrame.aspect_equip` + `aspect_equip_slot` (1-3) equips that aspect into that slot (`Player.try_aspect_equip`); if it already sits in another slot the two slots **swap**. Rules = the weapon equip's: only in `idle` or `walk` (never during a swing or its recovery, a skill, dash, parry, the barrage, the coil, after death), never while a **weapon** buff/form runs; a running Phantom Cut or a standing lantern does **not** block it; no lockout (several equips on consecutive ticks work). The aspect already in that slot, an unknown id, an empty id or a slot outside 1-3: nothing happens, no event. Event `aspect_equipped` (`entity_id`, `slot`, `aspect_id`, `previous` = the aspect that was in the slot, `swapped_slot` = the slot `previous` moved to, 0 when the new one came from the pool). Un-slotting an aspect never cancels what it already started (a placed lantern stays, a running Phantom Cut runs on). Breaking Edge keeps its retaliation-window requirement in whatever slot it is.

**Cooldowns are per aspect.** `Player.aspect_cooldowns` (aspect id -> ticks left), all counting down whether slotted or not, so re-slotting never resets or skips one. `Player.skill_cooldowns` is now a read-only per-slot view of it (`[cd of slot 1, slot 2, slot 3]`).

**Spirit Lantern** (`spirit_lantern`, skill action). Press: costs `SPIRIT_LANTERN_EDGE_COST` 30 Edge (spent on the press, `skill_started`), `skill_windup` `SPIRIT_LANTERN_WINDUP_TICKS` 10 (no movement; not invulnerable), `skill_active` 1 tick, `skill_recovery` 8, then free movement. On the first `skill_active` tick (press + 10) the lantern is placed at the player's feet (`lantern_placed`; no `skill_released`, no skill attack) and the aspect's cooldown `SPIRIT_LANTERN_COOLDOWN_TICKS` 900 (15 s) starts **from the placement**. Damage in the windup interrupts it like every skill: no lantern, the Edge is gone, and no cooldown is spent (it can be tried again at once). The lantern lives `SPIRIT_LANTERN_DURATION_TICKS` 300; pulse k (1-5) lands at placement + k x `SPIRIT_LANTERN_PULSE_INTERVAL_TICKS` 60 (the 5th on its last tick, then it expires the same tick). A pulse heals the player `SPIRIT_LANTERN_HEAL_PER_PULSE` 6 HP (never above max) and gives `SPIRIT_LANTERN_EDGE_PER_PULSE` 8 Edge (capped) when the player's **centre** is within `SPIRIT_LANTERN_RADIUS` **44 px** (inclusive) of the lantern. The boss is never affected. It does not block movement. One lantern per player: placing again removes the old one first (`lantern_expired` `replaced`, then `lantern_placed`). The player's death removes it (`lantern_expired` `death`, no further pulses); a new fight has none. Pulses resolve after the boss's hits of that tick.

**Phantom Cut** (`phantom_cut`, buff). A free action like the weapon active: no state change, allowed in any state except `dead`, `lightning_barrage` and `reaper_coil` (also mid-swing, mid-dash, mid-skill). Costs `PHANTOM_CUT_EDGE_COST` 40 Edge, cooldown `PHANTOM_CUT_COOLDOWN_TICKS` 1200 (20 s) from the activation, lasts `PHANTOM_CUT_DURATION_TICKS` 300 (active from the press tick through press + 299; `phantom_cut_ended` `expired` on press + 300), cannot be refreshed while it runs. While it runs **every normal swing that connects** (any weapon; not skills, the barrage or the coil spin) queues a phantom echo; a whiff queues nothing. The echo lands exactly `PHANTOM_CUT_DELAY_TICKS` 14 ticks after the real hit, on the boss wherever it is then (no range or arc check), if the boss is alive: damage = the swing's base damage (with its locked damage multiplier) x `PHANTOM_CUT_DAMAGE_MULT` 0.6, then the normal armor rule (x0.25, at least 1) or, while the posture is broken, x`COUNTER_DAMAGE_MULT` **without the Edge bonus**; posture = the swing's posture x `PHANTOM_CUT_POSTURE_MULT` 0.6 when not a counter. An echo never gains or spends Edge, never changes the combo, the swing's one-hit rule or the player's state, and never calls a finisher (no second dagger lightning strike). Echoes already queued still land after the buff expires; the boss's or the player's death drops the queue. Ends `expired` or `death` (`Player.die`, before `entity_died`).

### Echo Step, Stone Ward, Sprint (2026-10-21)

Core only (Claude Code); human-approved design, every number a first guess (nobody has played them). Three more aspects join `Aspects.ALL`, which is now **8**: `breaking_edge, gale_cut, moon_cleave, spirit_lantern, phantom_cut, sprint, echo_step, stone_ward` (menu order). `DEFAULT_EQUIPPED` is unchanged, old saves load unchanged (`is_valid_loadout` simply accepts the new ids). Numbers in `core/tuning.gd` (`SPRINT_*`, `ECHO_STEP_*`, `STONE_WARD_*`); `Aspects.display_name/kind/edge_cost/cooldown/duration` know them. New helper `Aspects.is_free_action(id)`: true for `phantom_cut`, `sprint`, `echo_step` (used on the press, no state change, any state but `dead`, `lightning_barrage`, `reaper_coil`, and not on the tick a barrage/coil is activated); the others go through the skill rules (idle, walk, or a swing's recovery). **Input: nothing new**: they sit in the Z/X/C slots like every aspect (`skill_pressed`, `aspect_equip`). A refused press does nothing, spends nothing and emits nothing.

| Aspect | kind | Edge | cooldown (from) | duration |
|---|---|---|---|---|
| Sprint `sprint` | `buff` | 20 | 720 (activation) | 180 |
| Echo Step `echo_step` | `skill` (free action) | 25 | 840 (placement = the press tick) | 120 until the recall |
| Stone Ward `stone_ward` | `skill` (state `ward`) | 30 | 720 (activation) | 60 |

**Sprint.** Free action. For 180 ticks (active from the press tick through press + 179; `sprint_ended` `expired` on press + 180) `Player.move_speed_mult()` is x`SPRINT_MOVE_SPEED_MULT` (2.0) (multiplied onto the weapon buff's own value, 1.0 for every weapon), so everything that moves at the walking speed is twice as fast: walking, the slowed movement in a swing (windup, active, recovery: x`ATTACK_MOVE_FACTOR`), the parry recovery, the Moon Cleave hold and the Stone Ward's slow walk. The dash, Gale Cut, Breaking Edge's step, the barrage blinks and the coil pull keep their own fixed speeds. No refresh while it runs. Ends `expired` or `death` (`Player.die`, before `entity_died`). The press tick already moves fast.

**Echo Step.** Free action, **no windup**. The press costs the Edge, starts the cooldown and places an **echo anchor** on the same tick where the player stands after this tick's movement, passed through `GameCore.arena_point` (in the arena, out of props). One echo at a time: while it exists the key does nothing (no cost). Recall due tick = placement + `ECHO_STEP_DELAY_TICKS` (120): the player is **teleported** to the anchor (again through `arena_point`; if the boss body covers it, the nearest free spot next to the boss via `_free_spot`, which also keeps out of props and the walls). The recall **cancels whatever the player was doing** (walk, swing, dash, parry, any `skill_*` state: back to `idle`, combo 1, a pending skill release dropped (a Moon Cleave hold spawns nothing), arc/lane skill attacks end, a flying projectile flies on); a raised **Stone Ward releases its shockwave first**, where the player stood (`ward_released` reason `recall`). A running **Lightning Barrage or Reaper's Coil is never interrupted**: the recall waits and happens on the tick it ends (at most `Weapons.reaper_coil_total_ticks()` = 58 ticks late; `waited` in the event). From the arrival tick the player is **invulnerable for `ECHO_STEP_INVULN_TICKS` 12 ticks** (arrival .. arrival + 11; `snapshot.player.invulnerable`, `echo_invuln_ticks` 12 on the arrival tick). The echo disappears on arrival, on the player's death (`echo_expired` `death`, after `entity_died`) or with a new fight. The recall resolves after the movement and the barrage/coil, before the player's swing and the boss's hits of that tick.

**Stone Ward.** A skill action (idle, walk, or a swing's recovery, which it cancels; not during windup, active, dash, parry, a skill, barrage, coil). **Instant raise**: on the press tick R the player enters the new state **`ward`** for exactly `STONE_WARD_DURATION_TICKS` 60 ticks (R .. R+59; `ward_ticks_left` 60 on R, 1 on R+59), no cancel. In the ward: movement x`STONE_WARD_MOVE_FACTOR` 0.3 of the walking speed (x2 with Sprint), **facing locked** to the direction it was raised in (move input, else aim, else facing), and no dash, attack, parry, skill, weapon active (right click is refused while the ward is up) or equip; the free actions (Phantom Cut, Sprint, Echo Step) still work. **Every hit that would damage the player is blocked** (`Player.take_damage` returns false: gold slam, sweep, combo slams, shards beams, stomp ring, the charge, anything else that calls it): no damage, no hurt state, no combo reset, no hurt i-frames; a gold attack is not parried (no parry posture, Edge or Breaking Edge window). The telegraph is used up, so one attack is blocked and stored once (a combo's two slams are two blocks). Its damage is **stored** (sum, capped at `STONE_WARD_STORE_CAP` 60). While the player is invulnerable for another reason (dash, hurt, blink, echo i-frames) nothing reaches the ward, so nothing is stored. On R+60 the player is `idle` and the ward **releases** a shockwave of `STONE_WARD_RADIUS` 64 px around the player: the boss is hit when `distance - BOSS_RADIUS <= 64`; damage = (`STONE_WARD_BASE_DAMAGE` 8 + stored x `STONE_WARD_STORE_MULT` 1.0) x the player's damage multiplier (katana buff 1.4), under the **skill hit rules**: armored x`ARMOR_DAMAGE_FACTOR` 0.25 (at least 1) plus posture `STONE_WARD_POSTURE` 12 + stored x 0.5 and `STONE_WARD_EDGE_GAIN` +10 Edge; while the posture is broken a counter x`COUNTER_DAMAGE_MULT` 4 with no Edge change. No knockback. Examples: nothing stored 2 HP; 20 stored 7 HP; 60 stored 17 HP (counter 272). The player's **death** ends it **without a release**. Edge and cooldown on the press.

### Save system (core)

`core/save_profile.gd` is the saved progress (`SaveProfile`): `runs_started`, `victories`, `defeats`, `best_victory_ticks` (0 = none yet), `last_result`, `weapon_id`, `equipped_aspects` (2026-10-21), plus `load_note` (why a profile is fresh instead of loaded; empty otherwise). `record_run_started()` and `record_result(result, ticks)` (returns true on a new best victory time) are the only mutators. Serialisation is versioned JSON (`VERSION` 1); reading is forgiving: invalid JSON, a missing/invalid version or a newer version gives a fresh profile with a `load_note`, and bad field values are cleaned (negatives and non-numbers become 0, unknown results/weapons are dropped).

`core/save_store.gd` reads and writes the file (`user://totoy_save.json`; the environment variable `TOTOY_SAVE_PATH` redirects it, the test runner sets it so tests never touch a real save). `save()` writes a temp file, keeps the previous save as `.bak` until the new one is in place, then removes it; `load_profile()` always returns a profile (the file, else the `.bak`, else a fresh one with a note if a file existed but was unreadable). Nothing in a running fight depends on it.

**Presentation use (implemented):** the arena saves only when the game was started from the title screen (the title sets `Engine` meta `totoy_persist`): it records a started run on load and on every restart, and the result (with `core.tick` as the time) on the `game_result` event; the title screen shows the record. Saved progress is a profile only: there is no mid-fight save, and no quest or inventory data exists yet.

`TelegraphSnapshot`: `id`, `owner_id`, `muzzle` (where the attack leaves the boss), `attack` (`gold_slam`, `gold_combo`, `red_sweep`, `red_shards`, `red_stomp`, `red_charge`), `kind` (`gold` = parry it, `red` = dodge it), `shape` + parameters, `start_tick`, `hit_tick`, `end_tick`.
- `circle`: `center`, `size` = radius
- `cone`: `center` = origin, `direction`, `size` = radius, `half_angle` (radians)
- `line`: `center` = start, `direction`, `size` = length, `width`
- `ring`: `center`, `size` = outer radius, `inner_size` = inner radius; **the inside (closer than `inner_size`) is safe**, the band is dangerous, the outside is safe

Boss attacks: `gold_slam` (one parryable slam), `gold_combo` (two parryable slams, the second `COMBO_GAP_TICKS` after the first; a perfect parry on the first breaks posture and cancels the second; phase 2 only), `red_sweep` (legacy attack identifier; gold parryable cone), `red_shards` (three lines), `red_stomp` (ring), `red_charge` (a line; the boss body travels along it while it is dangerous, so the boss `position` in the snapshot moves from `hit_tick` to `end_tick`; phase 2 only). The attack frames presentation shows come from the telegraph `attack` name; a combo has two telegraphs with different `hit_tick`s.

**Beam muzzle (`red_shards`).** The three beam lines leave the boss's **chest core**, not its feet. `Tuning.SHARDS_ORIGIN_OFFSET` (an offset from the boss position, which is its feet) is the single authoritative muzzle: when the attack commits the core computes `muzzle = boss.position + offset`, aims the middle line from the muzzle at the player, and starts all three warning/damage lines there (`telegraph.center == telegraph.muzzle`). It is locked for the whole attack and exposed as `TelegraphSnapshot.muzzle`. Presentation must draw the warning and the beam from that same ray (`center`, `direction`, `size`, `width`) and the chest flash at `muzzle`; it must not re-derive the origin from art. For every other attack `muzzle` is the boss position at commit.

The area is dangerous from `hit_tick` to `end_tick` inclusive; before that it is only a warning. Presentation draws the warning growing/filling toward `hit_tick` and may slow the visual for the final windup (the design's "final windup slows briefly").

`HudSnapshot`: `player_hp`, `player_max_hp`, `dash_cooldown_ticks`, `dash_cooldown_max`, `edge`, `edge_max`, `boss_hp`, `boss_max_hp`, `boss_posture`, `boss_posture_max`, `counter_window_ticks_left`, `skill_cooldown_ticks` (array of 3, ticks left of the aspect in each slot), `equipped_aspects`, `aspect_slots`, `aspect_cooldowns`, `phantom_ticks_left`, `phantom_duration` (see "Aspects"), `retaliate_ticks_left` (Breaking Edge is usable while this is above 0), `weapon_buff_duration`, `weapon_buff_cooldown_ticks`, `weapon_buff_cooldown_max`, `weapon_buff_edge_cost` (all for the equipped weapon), `weapon_cooldowns` (weapon_id -> ticks), `weapon_swap_lockout_ticks`, `weapon_swap_lockout_max`.

**Art contract:** presentation picks a frame from `art/build/sprites.json` using `<visual_id>_<state>_<direction>_<n>` for characters and `<visual_id>_<state>_<n>` for the boss (see `AGENTS.md` section 5 and `presentation/arena/animation.gd`). A missing frame falls back to a visible placeholder and logs a warning; it never crashes.

### Layered scenes: separate props (2026-10-27; the Stag glade and Lanternfen village)

A layered scene has a painted floor and props as separate sprites, so depth order and collision come from each prop's base line (docs/LAYERED_SCENE_PILOT.md). Core and presentation read the same two JSON files; the core loads no sprites. Code: `core/prop_scene.gd`; extractor: `tools/art/extract_props.py`.

- **Prop defs** `data/props/prop_defs.json` (made by the extractor from the magenta prop sheet): `props.<type>` = `{image, w, h, anchor [ax, ay], base_width, solid, colliders [[dx, dy, r], ...]}`. The anchor is the middle of the base in sprite pixels (from the top left); colliders are circles relative to the anchor, dy <= 0 (centres sit a little above the base line). Flat things (lower than 14 px) are decor: `solid` false, no colliders. An entry with `"locked": true` is hand-tuned and survives a re-run of the extractor.
- **Scene file** `data/scenes/<scene>_props.json`: `size`, `outline` (the walkable ground, clockwise, game pixels; edges on the world border are the openings), `boundary_radius`, `boundary_spacing`, `props[] = {id, type, x, y, flip?, shadow_radius?}` where x, y is where the prop's anchor stands in the world (`shadow_radius` is presentation's ground shadow, passed through). Adding or moving a prop is one line. A scene the hero walks also has `name`, `ground` (res:// path of the floor painting), `entries {id: [x, y]}`, `default_entry`, `exits [{id, rect [x, y, w, h], target_scene, target_entry}]`, `checkpoints [{id, position}]`, `npcs [{id, visual, position, face_left}]` (people are sprites, not props: they get a solid circle of `SceneDefs.NPC_RADIUS`), `objects [{id, kind, position, stand}]` (how to use a prop or spot: `position` its feet, `stand` where the hero uses it from, in front; the prop itself stays an ordinary placement) and, for the Stag fight room, `stag_start`, `stag_radius`, `fight_area`.
- **Core API** (`PropScene`): `load_defs()`, `load_scene(path)`, `placements(scene, defs) -> Array[Dictionary]` (what to draw: id, type, feet, flip, size, anchor, image, solid, shadow_radius?; the exact type `props_layer.gd` takes), `prop_colliders`, `scene_def(scene, id, margin)` (the `SceneDefs.get_def` shape, NPCs and objects included), `fight_room(scene)` ({start, radius, area}), `build(scene, defs)` (edge chain along the outline + every solid prop's circles, `visual_id` empty), `validate(scene, defs)` (empty when fine).
- **Presentation** draws each placement's `image` with its anchor on `feet` (mirrored when `flip`), y-sorted with the actors by `feet.y`: an actor whose feet are north of `feet.y` is drawn behind the prop. No occluder cut-outs. Sprites live in `art/src` (Codex converts the extractor's PNGs); the sprite name is the type id.

## Dialogue and story flags (2026-10-27)

Core side of chapter 1's NPC conversations: `core/dialogue_book.gd` (static lookups), `data/dialogue/chapter1.json` (the text; the lines in it are PLACEHOLDERS, the owner rewrites them), the conversation state in `ExploreCore`, `story_flags` in `SaveProfile`. Presentation draws the box and portrait from the snapshot; it holds no dialogue rules.

- **Data:** `npcs {npc id: [{when?: {flags: [...], not: [...]}, dialogue: id}, ...]}`: the first entry whose `when` holds is played (all `flags` set, no `not` flag set); the last entry has no `when` (validated). `dialogues {id: {speaker, portrait, set?: [flags], lines: [{text, speaker?, portrait?}]}}`. `DialogueBook.validate(book, npc ids)` checks every NPC of every scene has a conversation, every referenced dialogue exists, no empty lines, every line has a speaker, at most `MAX_TEXT_LENGTH` (110) characters per line and `MAX_LINES_TOTAL` (60) lines in the book. Flag names: 1-40 characters of a-z, 0-9, _.
- **Flow:** `interact_pressed` on an NPC target (idle or walk) emits `interact` as before and then `dialogue_started`; the hero stops (move and dash ignored, idle) and the world's other rules keep running. While talking, `interact_pressed` shows the next line (`dialogue_advanced`, `index`), after the last line it ends; `skip_pressed` ends it at once. Ending, finished or skipped, emits `dialogue_ended` {scene, npc_id, dialogue_id, skipped, flags_set} and one `flag_set` per NEW flag; a flag is set once. The press that ends a conversation never starts another. Objects and scenes without NPCs are unchanged.
- **Snapshot:** `ExploreSnapshot.dialogue` = `{npc_id, dialogue_id, index (0-based), count, speaker, portrait, text}`, empty when nobody talks; `story_flags` = every flag set. The typewriter effect, portraits, the box and the key mapping (E / Enter = `interact_pressed`, a skip key = `skip_pressed`) are presentation's. A press while the text is still typing should finish the typing in presentation and only send `interact_pressed` once the line is complete.
- **Core API:** `ExploreCore.set_story_flags(flags)` (restore a save, no events), `set_flag(flag)` (a story event such as the Stag binding sets one; emits `flag_set` with the next step), `has_flag`, `is_talking`.
- **Save:** `SaveProfile.story_flags` (an optional list in the JSON, version stays 1; unreadable entries are dropped, duplicates removed, at most 64); `reset_progress()` (a new game) clears it. Presentation saves on `flag_set` and passes `profile.story_flags` to `set_story_flags` when it builds the core of a scene.
- **Flags in the placeholder book:** `met_mira`, `met_tovan`, `met_edda` (Mira's follow-up changes once Edda has been heard).
